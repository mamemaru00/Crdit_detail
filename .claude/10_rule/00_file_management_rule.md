# ファイル管理ルール

## 概要
リポジトリ内に不要ファイルが蓄積することを防止するためのルール。
開発過程で作成されるレポート、スクリーンショット、テスト一時ファイル等はリポジトリに含めず、GitHub Issue等の外部手段で管理する。

## 禁止事項

### リポジトリに作成してはいけないファイル

| 種別 | パターン例 | 理由 |
|------|-----------|------|
| フェーズレポート | `PHASE*.md` | 開発過程の一時成果物 |
| テスト結果レポート | `*_RESULT.md`, `*_REPORT.md` | テスト結果は Issue に記録 |
| スクリーンショット | `screenshots/`, `issue*_*.png` | 画像は Issue に添付 |
| Issue対応テスト | `test_issue*` | 一時テストスクリプト |
| テスト出力 | `test_output.txt`, `test_results_summary.txt` | 一時出力ファイル |
| 作業メモ | `テキスト*`, `=*` | 個人作業用ファイル |
| report ディレクトリ | `report/` | フェーズレポート格納先（廃止） |

### .gitignore による強制除外
上記パターンはすべて `.gitignore` に登録済み。git add しても追跡されない。

## 代替手段

| 従来の方法 | 推奨される方法 |
|-----------|---------------|
| `PHASE3_TEST_REPORT.md` をリポジトリに作成 | GitHub Issue #XX のコメントに記録 |
| `screenshots/` にスクリーンショット保存 | GitHub Issue にドラッグ＆ドロップで画像添付 |
| `test_issue73_rate_limit.py` を作成 | テスト完了後に削除、または `tests/` 配下に正規テストとして整備 |
| `test_output.txt` にテスト結果出力 | GitHub Issue コメントにコードブロックで貼り付け |

## テストファイルの管理基準

### リポジトリに残してよいテストファイル
- `tests/` 配下の正規テスト（継続的に実行されるもの）
- `tests/test_data/` 配下のテスト用データファイル

### リポジトリに残してはいけないテストファイル
- ルート直下の `test_*.py`（Issue対応の一時テスト）
- `report/` 配下のテストスクリプト
- Phase別の一時テスト（`test_*_phase*.py`）

## 運用ルール

1. **Issue対応時**: テスト結果・検証レポートは GitHub Issue コメントに記録する
2. **E2Eテスト時**: Playwright のスクリーンショットは Issue に添付し、ローカルファイルは削除する
3. **レビュー時**: コードレビュー結果は PR コメントに記録する
4. **定期確認**: `git status` で untracked ファイルが蓄積していないか確認する
